# Contributing to Exthon

We appreciate your interest in contributing to Exthon! This document provides guidelines for contributing to the project.

## Code of Conduct

- Be respectful and inclusive
- Focus on constructive feedback
- Help others learn and grow

## How to Contribute

### Reporting Bugs

1. Check if the bug has already been reported
2. Provide a clear description and steps to reproduce
3. Include device info and Android version
4. Attach screenshots/logs if applicable

### Suggesting Features

1. Check existing feature requests
2. Clearly describe the feature and its benefits
3. Provide use cases and examples
4. Discuss implementation approach if possible

### Code Contributions

1. Fork the repository
2. Create a feature branch: `git checkout -b feature/your-feature`
3. Follow the code style and conventions
4. Write tests for new features
5. Commit with clear messages: `git commit -m "Add feature description"`
6. Push to your fork
7. Create a Pull Request with detailed description

## Development Setup

1. Clone the repository
2. Open in Android Studio
3. Build the project: `./gradlew build`
4. Run tests: `./gradlew test`

## Code Guidelines

- Use Kotlin for new code
- Follow Material Design guidelines
- Use MVVM + Clean Architecture patterns
- Add comprehensive comments for complex logic
- Keep methods focused and small
- Write unit tests for utility functions

## Pull Request Process

1. Ensure your code follows the guidelines
2. Update documentation if needed
3. Include screenshots/videos for UI changes
4. Request review from maintainers
5. Address feedback promptly
6. Ensure CI/CD passes all checks

## Testing

- Write unit tests for utilities
- Test on multiple Android versions
- Test on various device sizes
- Include integration tests for key flows

## Documentation

- Update README for major changes
- Add comments for complex algorithms
- Document new database schemas
- Include API documentation
